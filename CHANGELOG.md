## [0.2.5] — 2026-09-24

### Fixed
- **Фальшивые negative на Yii2/Yii + Linux/Ubuntu** — токен `yii` из требования
  «Опыт работы на Yii 2» не матчился к составным именам проектов в письме
  (`yii2filmcatalog`, `yii2shop`, `yii2gallery`) из-за границы слова; токен
  `ubuntu` из «Linux (Ubuntu)» не матчился к `Linux`. Добавлены синонимы:
  `yii2filmcatalog/yii2shop/yii2gallery` → `yii`, `ubuntu` → `linux`.
  GetCourse (Yii2 + Linux) с вердиктом `skip` 65% стал `apply` 100%.
- **Ложно-незакрытые абстрактные требования (trade-offs, Money Precision)** —
  стоп-слова `trade`, `offs`, `float`, `precision`: токены не раздували
  majority-порог, концепты «Architectural Management» и «точная денежная
  арифметика» закрывались по сигналам (ADR, money, идемпотентность).
- **Ложные отрицательные на ML/GenAI-вакансиях** — добавлены концепты:
  «GenAI/LLM/ML в production» (сигналы: Llama, DeepSeek, LLM, ML-модель,
  Random Forest, MLOps, 152-ФЗ, PII-маскирование), «Жизненный цикл ML/GenAI-решений»
  (MLOps, CI/CD, автоматизация пайплайнов, event-driven обучение моделей),
  «Опыт в архитектуре/системном анализе», «Кросс-функциональные команды /
  ведущие роли». Вакансия ML-архитектора (5 must): `skip` 83% → `apply` 100%.

### Added
- `context/03-ml-опыт-выжимка.md` — факты ML-опыта для генератора
  (5 сервисов с LLM/ML в production: Fraud Engine, Stable ID, Bundle ID,
  Domain ID, GeoMapping; Llama-3.3-70B, DeepSeek R1, Random Forest,
  метрики 92% F1 / 760–850 эл/с / 416K доменов / 98% покрытия).

## [0.2.4] — 2026-09-22

### Fixed
- **Ложно-отрицательные вердикты на англоязычных требованиях** — LLM-извлечение выдавало длинные англ. формулировки must-have, детерминированный матчер ищет латиницу в рус. письме/профиле и не закрывал 50-100% требований, роняя вердикт до `skip` со счётом 0.
  - `roleMismatch`: маркер `PHP (20\d\d+)` + окно 60 символов — билингвальный профиль «Go (3 года), PHP (2005+)» не даёт ложный `skip`.
  - `findText`: кириллические альты из синонимов — подстрокой, латиница — с границами слова.
  - Синонимы рус↔англ для абстрактных терминов: `query→запрос`, `optimization→оптимизац`, `migrations→миграци`, `tests→тесты`, `documentation→документаци`, `git→github`, `phpunit→тест/unit`, `culture→code review`, `high-load→highload/высоконагр` и др.
  - Стоп-слова: нарративные слова англ. требований (`branching`, `strategies`, `writing`, `maintaining`, `technical`, `professional`, `working` и др.) не раздувают majority-порог.
  - Majority: `found > missing` ИЛИ `found == missing` при `total >= 6` (50/50 для 6-токеновых требований; для `total <= 5` порог не открывается).
- **Языковые требования — в soft, не в mustHave** — промпт `extract.go` классифицирует «English working level», «Russian A1» как `soft`: не роняют вердикт до `skip`.
- **Концепт «документирование технических решений»** — trigger расширен на `documentat` (латиница из англ. требования), signal «техническая документация» на `ADR|api doc|архитектурн.решен`.
- **Концепты v0.2.4** — signals `retries/deadlines/идемпотентность` в концепт «эксплуатация»; `System Design` trigger `system.?design`; `NoSQL` без имён СУБД (мост через bridge, не через синонимы).

### Added
- **Регресс-тесты** — `TestRoleMismatchBilingualNoFalseSkip`, `TestEnglishReqCyrillicLetter`, `TestGitReqNarrativeStopwords` в `fit_test.go`; 3 сценария вакансий в `more_vacancies_check_test.go`.
- **Документирование ADR** — 10 ADR для Go-проектов, API-спецификации, code review как документирование (через `DefaultConcepts`).

### Verified (детерминированный матчер, 3 типа вакансий)
- Англ. Go highload: `apply` 70% (было `skip` 37%).
- Рус. PHP (10 must): `apply` 97% (было `skip` 0%).
- Edge K8s (честный пробел): `apply_with_caveats` 58% (корректно — не занижает, не завышает).

## [0.2.3] — 2026-09-19

### Fixed
- **Массовый unknown без missing ≠ skip** — клауза `unkN >= 3` в
  `finish()` удалена: 5 закрытых must-have + 3 unknown дают `caveats`,
  а не ложный `skip`. Регресс: `TestMassUnknown`,
  `TestMapCoverageMissingItemFallback`.
- **Fallback на coverage() при пропуске моделью** — если LLM-движок не
  разметил требование (len(cov.Items) != len(prompted)), `MapCoverage`
  вызывает `coverage()` напрямую: требование попадает в unknown/missing
  по факту, а не молча исчезает.

### Changed
- **Гибридный движок включён по умолчанию** — `settings.json`
  (пользовательский конфиг): `fitEngine: "llm"` включает LLM-матчер с
  цитатами + код-верификацию; детерминированный движок остаётся fallback.
- **Anti-fabrication** — таблица ограничений и глобальные запреты в
  системном промпте запрещают приписывать технологии из вакансии к
  буллетам письма. Честный пробел («не работал, готов освоить») остаётся.

### Added
- **Концепт «реляционные БД и SQL»** — триггеры `реляционн|база данных|бд|sql`,
  сигналы `pg_stat_statements`, `EXPLAIN`, `индексы`.

## [0.2.2] — 2026-09-19

### Fixed
- **Клаузная негация в `declinedInProfile`** (fit-вердикт): ограничитель
  профиля в одной клаузе («Transactional outbox на PostgreSQL:
  НЕ использовал») больше не отменяет факты профиля в других клаузах
  («PostgreSQL (глубокое знание)»). Раньше это давало ложный `skip`
  («обязательное требование не закрыто ничем») на вакансиях, где must-have
  по PostgreSQL/Postgres прямо закрыт профилем, — письмо такое не лечило.
- `declinedInProfile` стал двухпроходным: проход 1 — глобальные вето
  (прямое признание пробела «готов освоить X», хвостовое «X, опыта нет»);
  проход 2 — клаузные ограничители (backward-маркеры, заглавная частица
  «НЕ»), которые гасят токен только в своей клаузе. Метка моста
  («(мост к outbox)») чистым фактом не считается. Маркеры отрицания
  письма (`negRe`) не затронуты.
- 7 новых тестов: регресс на сам баг (Postgres) и шесть стражей конвенций
  профиля (ограничитель outbox остаётся declined, метка моста не факт,
  честные пробелы Python/Airflow остаются пробелами, под-клейм Kafka не
  отменяет факт Kafka, veto гибридного LLM-пути видит аннотацию).
  Живая верификация на реальном профиле (`context/`): postgres — факт,
  outbox без совета «впиши в письмо», Airflow — пробел.

## [0.2.1] — 2026-09-18

### Added
- **Fit-fix** — цикл автоисправления по fit-caveats (макс 3 итерации),
  аналог auto-fix для аудита. После генерации письма fit-движок находит
  требования, чей факт есть в профиле, но не попал в буллеты (нота
  «впиши в письмо, закроется полностью»); кнопка `fit-fix (N)` в панели
  вердикта отправляет письмо и список оговорок модели обратно — она
  дописывает недостающие факты в существующие буллеты, сохраняя остальной
  текст, а re-fit после каждой итерации останавливает цикл, когда
  исправимых оговорок не осталось. Поля `fitFix`/`fitCaveats` в
  `/api/generate` (валидация: оба обязательны, иначе 400), промпт
  `fitFixPrompt`, подсчёт исправимых оговорок на сервере (`sseDone.fitFixable`).
- **Контракт SSE для fit-fix**: поле `fitFixable` сериализуется всегда
  (без `omitempty`) — фронтенд различает «0 оговорок» и «нет данных»;
  при нуле кнопка скрывается.
- Тесты конвейера: интеграционный `TestFitFixableFromEvaluate`
  (регресс-гвард: факт «в профиле, но не в письме» доезжает до списка
  исправимых), end-to-end `TestGenerateEndpointFitFix` с проверкой наличия
  `fitFixable` в сыром JSON, валидация обеих половин условия (400 при
  letter без fitCaveats). 163 unit-теста (+12).

### Fixed
- Корзины покрытия: `FitFixableCaveats` сканирует `Covered` вместе с
  `Caveats` — маркер «впиши в письмо» генерируется в `Covered`
  (`SrcProfile`), и до фикса кнопка fit-fix не появлялась никогда.

## [0.2.0] — 2026-09-17

### Added
- **Фит-панель отклика** (`internal/fit`): вакансия разбирается на
  must-have/nice-to-have, каждое требование получает статус закрытия
  (письмо / профиль / мост / нет данных), вердикт apply /
  apply_with_caveats / skip и скор 0–100. Вердикт считает код, не модель:
  веса покрытия и пороги воспроизводимы и покрыты тестами.
- **Гибридный LLM-матчинг** (`internal/fit/map.go`, настройка `fitEngine`):
  модель размечает покрытие письма с обязательной цитатой, код проверяет
  цитаты и отрицания («опыта нет» ≠ закрыто) и при любой ошибке
  откатывается на детерминированный матчер. Пустая настройка — матчер
  на правилах: ноль токенов, ноль задержек.
- **Динамические концепты** (`internal/fit/concepts.go`): концепты
  покрытия генерируются LLM из профиля кандидата и кэшируются в
  `~/.config/covercraft/concepts.json` с инвалидацией по SHA-256 профиля;
  валидация (≥2 trigger-термина по ≥4 рун, ≥2 signal-группы), fallback
  на встроенные 12 концептов при любой ошибке.
- **Must-have чек-лист в промпте письма** (`internal/cover`): генератор
  получает обязательные требования вакансии и закрывает их в буллетах;
  аудит (`internal/audit`) ловит потерянные факты и дубли метрик.
- Настройка `fitEngine` в UI и `~/.config/covercraft/settings.json`.

### Changed
- **Направленные отрицания**: «готов освоить» гасит только то, что стоит
  после маркера, «не использовал» — всю клаузу: мост «bash-автоматизация
  → готов освоить Python» больше не выдаёт Python за опыт и не прячет Bash.
- Токен-матчинг: синонимы (limits → «rate limiting», logbroker → kafka),
  `sql`/`rest`/`api` не стоп-слова (реальные навыки в вакансиях),
  `business`/`critical` — стоп-слова (эпитеты); триггеры концепта
  «эксплуатация» дополнены алерт/инцидент.
- `roleMismatch`: билингвальный Go+PHP профиль больше не даёт ложный
  вердикт «роль вакансии другого профиля».

### Точность на реальных вакансиях
| Вакансия | до 0.2.0 | после |
|---|---|---|
| Senior Go (highload, AI-интеграция) | caveats, 96 | apply, 100 |
| SRE / платформа разработки | caveats, 92 | apply, 100 |
| Senior PHP (маркетплейс) | caveats, 70 | caveats, 92 |
| Data Engineer | caveats, 65 | caveats, 78 |

Реальные пробелы (PySpark, S3, RabbitMQ) система по-прежнему называет
честно — не приукрашивает.

Тесты: 151 unit-тест (на 0.1.3 — около 60).
