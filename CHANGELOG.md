## [0.5.0] — 2026-10-17

Аудиторные правила кандидата вынесены из Go-кода в `context/.audit-rules.md`
(плоский каталог профиля, вне репозитория). Промпт и аудит объявлены одним
контрактом, три ловушки регулярок, молча пропускавшие выдуманные факты, закрыты.

### Added

- **Профильные правила аудита в данных.** `internal/audit/rules.go`: парсер
  `context/.audit-rules.md` (секции `obligations`, `metricRules`, `stackForbidden`,
  `claimableTerms`, `infraDomainTerms`, `infraNeutralWords`), перечитывается на
  каждом `/api/generate`. Без файла профильные проверки выключены, сервер пишет
  `warn` в лог (`TestLoadProfileRules*`, `TestTemplateGivesWorkingProtection`).
- **Документация и шаблон:** `docs/UNIVERSALITY.md`,
  `docs/templates/.audit-rules.md`; README — раздел про адаптацию.
- **`audit.PromptContract`** — источник правды по инвариантам письма:
  `DefaultSystemPrompt` берёт маркеры, аудит — тексты предупреждений
  (`TestDefaultSystemPromptCoversAuditContract`,
  `TestAuditContractEntriesAreEnforced`).
- **Регрессионные корпуса на чужом профиле:** `TestGoldenUniversal` (fit),
  `TestAuditUniversalNoForeignFalsePositive` (audit),
  `TestNoCandidateDataInEngine`, `TestProfileRulesOnlyFromContextDir`.

### Fixed

- **«Адаптация под ваш стек» засчитывалась за строку стека** — префикс искался в
  любом месте строки, письмо без «Стек: » проходило проверку.
- **ASCII-классы Go regexp.** `\b`/`\w`/`[[:alpha:]]` не работают после
  кириллицы: «искусственный интеллект» больше не проходил молча. Заменено на
  `\p{L}`, ловушка описана в `docs/UNIVERSALITY.md`.
- **CamelCase-guard считал инструментом обычные слова** («CPU заявлен как свой
  инструмент», «RPS», «SSD»): словарь оборудования, протоколов, форматов и метрик
  вынесен в `infraCommonWords`; выдуманные инструменты (DWH) ловятся как раньше.
- **Ложные срабатывания на чужом корпусе:** 11 → 2 (Java Kafka, React DWH),
  Python — 0. Перечисления в заголовке буллета и ссылки вакансии на
  отсутствующие технологии больше не читаются как заявки.

### Changed

- **Строка контактов обязательна только если контакты есть в профиле.** Проверка
  переехала из `Check` в `CheckProfile`: у кандидата без контактов в `context/`
  она требовала телефон или ник.
- **Профильные проверки требуют `.audit-rules.md`** — ломающее изменение для
  кандидатов без файла (инварианты, факты и атрибуция метрик идут в тишину).
  Для чужих фикстур добавлены синтетические профили devops/frontend.

## [0.4.0] — 2026-10-08

Пресеты системного промпта, режим `qa`, стилевая модалка подтверждения вместо
нативного `confirm`.

### Added

- **Пресеты системного промпта.** Именованные шаблоны под разные цели: селектор
  `presets` в панели `system.prompt`, кнопки `new preset` / `save preset` /
  `edit preset` / `del preset`. Создание и правка — модалкой с именем и текстом.
  Хранение — `~/.config/covercraft/presets.json` (паттерн settings.json: 0600,
  атомарная запись). Пресет — шаблон: выбор копирует текст в поле, правки
  сессионные, в шаблон уходят только по save/edit; активный пресет
  восстанавливается при старте. Новые эндпоинты:
  `GET/POST/PUT/DELETE /api/presets` и `POST /api/presets/active`. Пайплайн
  генерации не тронут: `systemPrompt` приходит из поля, compose и
  `reset default` как раньше.
- **Источник системного промпта в `prompt-sentinfo`.** После генерации строка
  «в модель ушло» называет источник (пресет «имя» / ваш / дефолтный) и первую
  строку отправленного `usedSystemPrompt` — вопрос «какой промпт ушёл в модель»
  закрыт без отладки.
- **Режим `qa` у пресетов.** Пресет помечается как «ответы рекрутеру»: сервер
  пропускает разбор вакансии (extract), fit-вердикт и письменный аудит
  (`CheckWithMust`, `CheckProfile`, предупреждение о пустом профиле) — отвечать
  рекрутеру не просьбой извлечения требований. Дефолт (`cover_letter`) и кастомный
  промпт — полный пайплайн, как раньше. Фит-панель в UI скрыта без вердикта и
  объяснения.
- **Стилевая модалка подтверждения `uiConfirm`.** Нативный `confirm()` в WebKit
  рисует чужеродное окно «JavaScript — http://127.0.0.1…» ; заменён на CSS-модалку
  в стиле приложения (классы `.preset-modal`). При открытом подтверждении кнопки
  панели пресетов блокируются классом `.confirm-open`, кнопки самой модалки
  (ok / отмена) активны.

### Fixed

- **Состояние «без пресета».** Снятие привязки оставляло поле с текстом бывшего
  пресета; теперь возвращается `defaultPrompt`, при несохранённых правках
  показывается `uiConfirm` с вопросом о замене.
- **Открытие модалки «новый пресет».** В ветке create обращались к
  `els.presetMode`, которого не было в объекте `els` — TypeError рушил скрипт.
  Добавлено поле в `els`, логика openPresetModal унифицирована для create/edit.
- **Потеря `currentPresetMode` после удаления пресета.** `delPreset` не сбрасывал
  сессионную переменную, следующий generate мог взять режим удалённого пресета.
  Теперь сбрасывается в `""`.

### Changed

- **Валидация `mode` на сервере.** Пустой `mode` при создании = `cover_letter`;
  неизвестный `mode` → HTTP 400 «неизвестный режим пресета». PUT с пустым `mode` —
  «не менять».
- **Константы режимов.** Все литералы `"qa"` в `server.go` заменены на
  `presets.ModeQA`. Поле `Mode` в `streamParams` очищено от ложного тега
  `json:"mode"`.

### Tests

- `TestPresetsAcceptHugePrompt` — сервер принимает пресет с огромным текстом.
- `TestPresetsSurviveRestart` — пресеты сохраняются и восстанавливаются.
- `TestPresetModeSelect` — регрессия на наличие `presetMode` в `els` и селектора режима.
- `TestPresetModeBackfill` — старые пресеты без `mode` считываются как `cover_letter`.
- `TestUiConfirmModal` — наличие модалки подтверждения и отсутствие боевого `confirm` / `alert`.
- Негативный тест на неизвестный `mode: "факс"` → HTTP 400.

### Internal

- Документация полей `FitMaxIter` и `Mode` в `generateRequest` приведена в порядок.
## [0.3.5] — 2026-10-07

Детерминированная генерация писем (temperature 0.2), обязательные GO-PRIMARY
сервисы (Stable ID, Fraud Engine, Bundle ID, Domain ID, Geo-mapping),
расширенный лимит слов (250/350/400), защита ML-секций от вырезания композером
при go-primary/fullstack роли.

### Added

- **Temperature 0.2 по умолчанию.** Без явного значения провайдер подставлял
  0.7–1.0 — одно письмо давало разные результаты, модель «случайно» теряла
  Go-сервисы. Теперь детерминизм на уровне чата (llm.Client.Temperature +
  Settings defaults).
- **GO-PRIMARY обязательства.** Пять Go-сервисов (Stable ID, Fraud Engine,
  Bundle ID, Domain ID, Geo-mapping) обязаны попадать в письмо при go-primary
  роли (маркер `\bgo\b` в тексте вакансии). Аудит называет теряемый факт точно;
  автоправка возвращает срезанный сервис. Триггер роль-scoped — PHP-вакансия не
  получает Go-обязательств.
- **Расширенный лимит слов.** Базовый: 250 (было 200). При 6+ must-have: 350
  (было 300). Для GO-PRIMARY: 400. Лимит в согласии с v4 промптом (§1).
- **Защита ML/Go-секций от дропа.** Для go-primary и fullstack ролей композер не
  вырезает разделы «5 ML-ПРОДАКШН-СЕРВИСОВ», «КАРТА МЕТРИК», «1. GO», «2. GO»,
  «GO-ПРОЕКТЫ». Без защиты ML-секции считались нерелевантными IPTV-вакансии без
  ML-требований → модель физически не могла написать факт, которого нет в промпте.

### Fixed

- **Письмо на 380 слов при 7 требованиях ругалось.** Жёсткие 250/300 против
  промпта «250 допустимо при 6+ требований» — цикл автоправки повторялся
  бесконечно (живой кейс, октябрь 2026).
- **Live SRE-письмо (210 слов) ругалось на превышение.** Новый базовый лимит 250
  закрывает регрессию.

## [0.3.4] — 2026-10-04

Compose видит выжимку фактов разделов (точный отбор вместо угадывания по
заголовку), анонимизированный факт ИИ-инструментов принят аудитом и фитом,
AI-агентные требования закрываются анонимизированным буллетом.

### Fixed

- **Анонимизированный outward-факт ИИ-инструментов признавался фабрикацией.**
  `checkAIClaim` подтверждал заявку только конкретными vendor-именами
  (`aiToolNames`), а профиль хранит анонимизированную форму без имён → письмо
  получало warning о фабрикации и уходило в «не использую ИИ-инструменты».
  Добавлен подтверждающий `aiToolAnonFactRe`, `checkAIClaim` принимает имя ИЛИ
  анон-факт после вырезания запретных блоков.
- **AI-агентные требования вакансии не закрывались анон-буллетом.** Концепт
  «агентские системы и Tool Use» требовал сигналы «агент / agent / tool use /
  function call», которых в честно обезличенном письме нет. Сигналы расширены
  анонимизированными маркерами агентного процесса — «постановка задач»,
  «делегирование», «ежедневная практика», «контроль…инженер», «проходит…review»:
  требование «выстраивать рабочий процесс с AI-агентами» закрывается
  анон-буллетом, а не уходит в оговорку.
- **Compose-панель не прокручивалась.** Крупный кастомный промпт или длинные
  блоки dropinfo/sentinfo раздували панель выше окна, а на десктопе body/main
  имеют `overflow:hidden` — кнопки (compose/вернуть/reset) уходили ниже видимой
  области. Панель ограничена по высоте и прокручивается внутри, строка кнопок
  липнет к низу.

### Added

- **Compose видит выжимку фактов каждого раздела профиля (excerpt), а не только
  заголовки.** `Section` получил поле `Excerpt`; `cover.ProfileSections` нарезает
  выжимку первых непустых строк текста (без строк-заголовков, ≤240 байт по границе
  руны, `…` при обрезке). Композер судит релевантность по фактам, а не по
  заголовку, — риск вырезать must-have-раздел снижен. Защищённые разделы
  (ФАКТЫ-ОГРАНИЧИТЕЛИ, КОНТАКТЫ) excerpt не получают: невырезаемы по построению,
  контакты не утекают в лишний LLM-вызов.
  `prompt.isProtected` экспортирован как `IsProtected` — единый источник списка.

### Internal

- ADR без числа в тестовых фикстурах fit: число `(10)` не несёт смысла для
  матчинга, профильные факты используют голый `ADR`.

## [0.3.3] — 2026-10-02

Честная сверка фактической отправки с композером, кириллические мосты фита,
триггеры концептов под живые ложные срабатывания, честные пробелы в audit.

### Fixed

- **Честный пробел в VoIP-вакансии помечался «фабрикацией».** Точка внутри токена
  (`sip.js`, `go.mod`, версии) рвала клаузу на две в audit `claimPositively`,
  отрицание «не работал / готов освоить» уезжало во вторую клаузу, и честный блок
  адаптации (SIP/WebRTC/FreeSWITCH) выглядел утвердительной заявкой → четыре
  ложных warning'а о выдумке, auto-fix мог испортить честный пробел. Точка
  считается концом предложения только при пробеле/конце после неё
  (`\.(?:\s+|$)`). Положительные кейсы фабрикаций остались помеченными
  (SRE/fullstack-регресс-тесты).
- **Фит-вердикт не гасился при эхе, считался по уцелевшему письму.** (35b41e7)
- **Автоправка аудита отправляет модели только релевантные секции.** (977f147)
- **Замечание-эхо не слалось модели как дефект письма.** (052b760)

### Added

- **Кириллический мост фита** (`bridgeHitFallback`): русское требование без
  латинских токенов («опыт с очередями сообщений» = RabbitMQ) закрывается мостом
  по ключевым словам, но только при подтверждении опыта тем же регэкспом в
  письме/профиле — иначе честный пробел.
- **Дополнительные формы триггеров концептов** под живые ложные срабатывания:
  «реляционные БД и SQL» — `оптимизац.{0,20}запрос`, `план.{0,20}запрос`,
  `профилирован`, `медленн.{0,15}запрос`; «продуктовая разработка полного цикла» —
  `вывод.{0,20}прод`, `выкат`, `деплой`. Требования про оптимизацию медленных
  запросов и вывод в прод закрываются по признакам, а не уходят в «проверь
  вручную».

### Changed

- **Обязанность (duty) больше не тянет вердикт до Caveats.** Раньше duty,
  закрытая мостом (SrcBridge) или ушедшая в unknown, оставалась в `f.Caveats` и
  через `len(f.Caveats) > 0` роняла вердикт в Caveats при закрытых must-have.
  Теперь вердикт считают только оговорки по требованиям; обязанности выводятся
  отдельной строкой совета (симметрично `dutyGaps` в missing) и исключены из
  сводного unknown-совета во избежание задвоения.

### Internal

- **Бенчмарки горячего пути `Evaluate`.** (16c9476)
- **Golden-тесты вердиктов возвращены в репозиторий.** (6e57731)
- `bridgeHitFallback` итерирует по отсортированным ключам `bridges`, а не по
  карте — при совпадении нескольких мостов («мониторинг метрик» → victoriametrics И
  observability) вердикт детерминирован между прогонами.
## [0.3.2] — 2026-10-01

Наблюдаемость фактической отправки, защита автофикса от вывода профиля вместо
письма, ограничение кэша регулярных выражений.

### Fixed

- **Автофикс выводил профиль вместо письма.** `isPromptEcho` исключал из подсчёта
  строки, найденные в `origLetter` — исходном письме пользователя: fit-fix вкладывает
  письмо в user-промпт, ответ повторяет его дословно, и правка ложно считалась
  эхом. Но письмо для следующей итерации берётся из результата **предыдущей**, и
  прошедшее как «письмо» эхо попадало в `origLetter`: все его строки помечались
  «собственный текст письма» — детектор оправдывал себя, доля падала в ноль. Итог:
  «несколько попыток автофикса → профиль на экране».

  Исключение теперь только для строк, которых **нет в профиле**: совпавшая с
  фактом строка письма — текст письма; взятая и из письма, и из профиля — цитата
  факта, которую письмо обязано сохранить. Эхо воспроизводит профиль целиком,
  поэтому его строки почти всегда есть в `profile` и детектор снова срабатывает.
- **При отклонённом эхо фит-вердикт не считался.** Эхо отбрасывалось, но вердикт
  по нему уже ушёл в UI вместе со сработавшим автофиксом: фронтенд останавливал
  автофикс по недостоверным данным. При отклонённом эхе вердикт не отправляется.
- **Структурный признак эха не срабатывал на живом профиле.** Регулярка ловила
  только `##`/`###`, а профиль открывает им файл верхнего уровня
  (`# КАРТА МЕТРИК`): на живом эхе было два `##` и одна `#` — до порога в три
  заголовка не доходило. Теперь считается любой markdown-заголовок `#`–`######`.
- **Диагностика перебора по длине показывала «0 символов».** Проверка длины
  письма обнуляла `letter` до подсчёта, в предупреждение попадал `len("")`.
  Длина меряется до обнуления — иначе диагностика молчала о неприемлемом размере
  ответа.

### Added

- **Наблюдаемость фактической отправки** (событие `done` SSE): `appliedDropSections`
  (дропы, реально вырезанные из профиля — меньше запрошенного, если профиль
  правили между вызовами композера), `usedUserPromptBytes`, `usedProfileBytes`,
  отправленный системный промпт и предупреждение о prompt ≥8 КБ и ≥4× от дефолта.
  `usedUserPromptBytes` и `usedProfileBytes` сериализуются всегда, чтобы UI
  отличал «0 байт» от «поле не пришло».
- Регрессионные тесты на живых письмах: PHP-архитектор (кириллическое требование
  по БД, `internal/fit`), SRE, AI-product, fullstack — правые требования, которые
  ранее ложно уходили в `missing`. Живой прогон (`TestAFLTLiveEndToEnd`) выключен
  по умолчанию: требует `CC_LIVE=1` и платных вызовов, ключ — только из
  `settings.json`.

### Changed

- **Кэш скомпилированных регулярок получил потолок ёмкости** (`wordReCacheMax`).
  Ключи приходят из `reqTokens(текст вакансии)`, то есть из пользовательского
  ввода, а `sync.Map` не сбрасывается никогда: на вакансии с 4 000 уникальных слов
  копились 4 006 записей и 9,5 МБ удержания (~2,4 КБ на запись) — поток разных
  вакансий давал рост без предела. Счётчик на `atomic.Int64`, запись через
  `LoadOrStore` вместо пары `Load`+`Store`. При переполнении регулярка
  компилируется заново — медленно ровно настолько, насколько вакансия
  патологична, зато память ограничена.

### Internal

- `streamGenerate` принимал 14 позиционных параметров, из которых шесть подряд
  типа `string` (`system`, `user`, `vacancy`, `profile`, `origLetter`).

  размечает покрытие письма с обязательной цитатой, код проверяет цитаты и
  отрицания («опыта нет» ≠ закрыто) и при ошибке откатывается на детерминированный
  матчер. Пустая настройка — матчер на правилах: ноль токенов, ноль задержек.
- **Динамические концепты** (`internal/fit/concepts.go`): концепты покрытия
  генерируются LLM из профиля и кэшируются в
  `~/.config/covercraft/concepts.json` с инвалидацией по SHA-256 профиля;
  валидация (≥2 trigger-термина по ≥4 рун, ≥2 signal-группы), fallback на
  встроенные 12 концептов при ошибке.
- **Must-have чек-лист в промпте письма** (`internal/cover`): генератор получает
  обязательные требования вакансии и закрывает их в буллетах; аудит
  (`internal/audit`) ловит потерянные факты и дубли метрик.
- Настройка `fitEngine` в UI и `~/.config/covercraft/settings.json`.

### Changed
- **Направленные отрицания**: «готов освоить» гасит только то, что стоит после
  маркера, «не использовал» — всю клаузу: мост «bash-автоматизация → готов
  освоить Python» больше не выдаёт Python за опыт и не прячет Bash.
- Токен-матчинг: синонимы (limits → «rate limiting», logbroker → kafka),
  `sql`/`rest`/`api` не стоп-слова (реальные навыки в вакансиях),
  `business`/`critical` — стоп-слова (эпитеты); триггеры концепта «эксплуатация»
  дополнены алерт/инцидент.
- `roleMismatch`: билингвальный Go+PHP профиль больше не даёт ложный вердикт
  «роль вакансии другого профиля».

### Точность на реальных вакансиях

|---|---|---|

| Senior PHP (маркетплейс) | caveats, 70 | caveats, 92 |
| Data Engineer | caveats, 65 | caveats, 78 |
